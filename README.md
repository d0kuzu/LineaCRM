# Linea CRM

В Customers команда ведёт компании, контакты и историю общения. В Sales можно назначить ответственного за лид, преобразовать его в сделку и провести по этапам на канбан-доске до закрытия. В Tasks и Calendar сотрудники планируют задачи и встречи и связывают их с клиентами и сделками. Эти разделы загружают данные из PostgreSQL через серверный API.

## Структура

- `front/` — текущий фронтенд на React, TypeScript и Vite, его настройки и зависимости.
- `front/design/` — макеты и материалы дизайна.
- `front/presentation/` — презентация проекта.
- `front/DEVELOPMENT_PLAN.md` — план разработки.
- `back/` — серверная часть LineaCRM на основе ветки `empty-pattern` проекта `d0kuzu/aveda_ai`. В ней четыре Go-сервиса со своими зависимостями и Dockerfile.

## Бэкенд

Публичная точка входа — `api-gateway` (локально порт 8085). `auth-service` хранит аккаунты, сессии и состав рабочих пространств в `auth_db`. В `crm_db` сервис CRM хранит компании, контакты, лиды, сделки, задачи и встречи. `ai-service` хранит ассистентов, чаты и сообщения в `ai_db`. [Настройки, запуск и контракт API](back/README.md)

При первом входе зарегистрируйте аккаунт. Можно создать пространство с ролью администратора или передать свой ID администратору существующей команды. После входа в пространство стартовый экран — Customers. Раздел показывает доступные пользователю карточки и историю выбранной команды.

## Порядок разработки CRM

| Этап плана | Состояние и ближайшие работы | Экраны |
| --- | --- | --- |
| 2. Клиенты | Работают списки, карточки, связи, фильтры, теги, сегменты и история взаимодействий. Администратор настраивает поля компаний и контактов. Карточки связаны со сделками, задачами и встречами. | Customers подключён к API. В формах и карточках видны поля команды. Общий поиск находит доступных клиентов. |
| 3. Продажи | Работают лиды, конверсия в сделку, привязка клиентов и настраиваемые воронки. Руководитель и администратор могут передать сделку другому сотруднику. История сохраняет смену ответственного, параметры и переходы между этапами. | В Sales подключены таблица и канбан с фильтрами по воронке, этапу, ответственному, валюте и сумме. |
| 4. Ежедневная работа | Работают назначение задач, приоритеты, сроки, список просроченных и встречи с участниками. Следующие работы — напоминания, рабочий стол и отчёты по сохранённым данным. | Задачи, календарь дня и недели и поиск подключены к API. |
| 5–7. Ассистент | Диалог связывается с сотрудником и пространством. При открытии из карточки сервер проверяет доступ к записи. Изменение CRM по предложению модели проходит через то же доменное API после подтверждения. | Боковая панель и экран ассистента |

Маршруты компаний и контактов доступны через `/crm/workspaces/{id}/…` на шлюзе. Шлюз устанавливает личность из JWT, CRM проверяет актуальное членство через Auth и ограничивает выборку по пространству, роли и ответственному. Составной внешний ключ в `crm_db` связывает контакт с компанией того же пространства. Миграция `004_customer_history.sql` добавляет журнал карточек. Изменение и запись в журнале сохраняются одной транзакцией.

Когда дойдём до ассистента, `ai-service` будет получать контекст через API `crm-service` от имени сотрудника. Так открытие карточки в браузере и запрос той же карточки из чата пройдут одинаковые проверки доступа.

В исходной ветке уже есть список и поиск чатов, загрузка истории и WebSocket. Текущий WebSocket обслуживает оператора внешнего канала. Отправленное в него сообщение сохраняется как ответ оператора, а для Twilio может уйти клиенту. Для внутреннего ассистента потребуется отдельная отправка от имени сотрудника, создание диалога, идентификаторы сообщений и продолжение истории с последнего полученного сообщения. Идентификатор собеседника внешнего канала `chats.customer_id` и ID контакта CRM нужно связывать явно.

## Запуск фронтенда

Для работы Customers запустите PostgreSQL, `auth-service`, `crm-service` и `api-gateway` по инструкции для сервера. Затем из корня проекта выполните команды ниже.

```sh
cd front
npm ci
npm run dev
```

Vite пересылает запросы `/auth` и `/crm` на `http://127.0.0.1:8085`. Адрес другого шлюза задаётся в `LINEA_GATEWAY_URL`. Для опубликованной сборки настройте на веб-сервере проксирование этих префиксов на gateway с сохранением пути. [Настройки фронтенда](front/README.md)

## Проверка и сборка

Из корневой папки проекта:

```sh
npm --prefix front run build
```

Команда проверяет типы TypeScript и создаёт сборку в `front/dist/`.

Подробнее о фронтенде — в [front/README.md](front/README.md).
